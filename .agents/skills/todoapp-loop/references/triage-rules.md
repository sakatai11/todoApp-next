# Triage Rules（スコアリング・ルーティング基準）

todoapp-loop の Phase 2 で使用する判定基準。運用しながらこのファイルを調整する。

## スコアリング表

| 候補の種類                           | スコア | 判定方法                                         |
| ------------------------------------ | ------ | ------------------------------------------------ |
| security系CI失敗                     | 100    | workflowName が `security-review` / npm audit 系 |
| 本番バグ                             | 80     | Issue に `bug` ラベル                            |
| その他のCI失敗                       | 60     | react-doctor 等、security以外のworkflow失敗      |
| 機能Issue                            | 40     | Issue に `enhancement` / `feature` ラベル        |
| 改善系（リファクタ・docs・UI微調整） | 20     | 上記以外のIssue                                  |

同スコアの場合は更新日時が新しいものを優先する。

## ルーティング表

| 条件                                            | 委譲先                 | 備考                         |
| ----------------------------------------------- | ---------------------- | ---------------------------- |
| security-review.yml / npm audit のCI失敗        | `fix-security-ci`      | run URL を渡す               |
| 受け入れ条件が明確なIssue（バグ・機能・UI）     | `todoapp-orchestrator` | Issueトリガーで起動          |
| CI失敗だがsecurity系でない                      | `todoapp-orchestrator` | バグ修正トリガーとして正規化 |
| 下記「委譲禁止リスト」該当 / 受け入れ条件が曖昧 | 委譲しない             | triage-inbox へ理由付き記録  |

## 受け入れ条件が「明確」の判定基準

以下を**すべて**満たすこと。1つでも欠ける場合は inbox 行き:

1. 期待する動作（または再現手順）が具体的に書かれている
2. 完了条件が検証可能（「〜が表示される」「テストが通る」等）
3. 変更範囲が推定できる（対象機能・画面・APIが特定できる）

## 委譲禁止リスト（常に inbox 行き）

スコアに関係なく自動委譲しない:

- Firestoreスキーマ・データ構造の変更を伴うもの
- 認証まわり（NextAuth / Firebase Auth / middleware.ts / RBAC）の変更
- 依存パッケージのメジャーバージョンアップデート
- 破壊的変更（既存APIのレスポンス形式変更等）
- インフラ・デプロイ設定（vercel.json / GitHub Actions workflow自体）の変更
- 工数が明らかに大きいもの（複数機能の横断改修等）

## 上限値

| 項目                          | 値         |
| ----------------------------- | ---------- |
| 1サイクルの着手上限           | 2件        |
| 1サイクルのPR上限             | 2件        |
| verifier reject 時のリトライ  | 1回        |
| stale判定（進行中の放置日数） | 7日        |
| inbox 警告しきい値            | 未処理10件 |
| 処理済み履歴の保持            | 直近30件   |
